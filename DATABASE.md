# Schéma de Base de Données (Supabase)

Pour faire fonctionner le système d'authentification et d'amis, vous devez créer les tables suivantes dans votre instance Supabase.

## Table `roles`

Cette table stocke les rôles utilisateurs (ex. User, Admin).

```sql
create table public.roles (
  id bigint generated by default as identity primary key,
  role text unique not null
);

insert into public.roles (role) values ('User'), ('Admin');
```

Pour promouvoir un admin manuellement :

```sql
update public.profiles set id_role = 2 where id = '<uuid>';
```

## Table `profiles`

Cette table stocke les informations publiques des utilisateurs.

```sql
create table public.profiles (
  id uuid references auth.users on delete cascade not null primary key,
  username text unique,
  avatar_url text,
  id_role bigint references public.roles(id) default 1 not null,
  updated_at timestamp with time zone,

  constraint username_length check (char_length(username) >= 3)
);

-- Activer Row Level Security
alter table public.profiles enable row level security;

-- Politiques de sécurité
create policy "Public profiles are viewable by everyone." on public.profiles
  for select using (true);

create policy "Users can insert their own profile." on public.profiles
  for insert with check (auth.uid() = id);

create policy "Users can update own profile." on public.profiles
  for update using (auth.uid() = id);
```

## Table `friendships`

Cette table gère les relations d'amitié.

```sql
create table public.friendships (
  id bigint generated by default as identity primary key,
  user_id uuid references auth.users not null,
  friend_id uuid references auth.users not null,
  status text check (status in ('pending', 'accepted', 'declined')) default 'pending',
  created_at timestamp with time zone default timezone('utc'::text, now()) not null,

  unique(user_id, friend_id)
);

```

## Table `playlist`

Cette table stocke les playlists jouables dans le blindtest.

```sql
create table public.playlists (
  id bigint generated by default as identity primary key,
  spotify_playlist_id text unique not null,

  name text not null,
  cover_url text,

  is_visible boolean default false not null,
  activation_date timestamp with time zone,

  created_at timestamp with time zone default timezone('utc'::text, now()) not null,
  updated_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- Activer Row Level Security
alter table public.playlists enable row level security;

-- Tout le monde peut consulter les playlists
create policy "Playlists are viewable by everyone." on public.playlists
  for select using (true);
```

## Table `songs`

Cette table stocke les morceaux importés depuis Spotify et enrichis avec les données iTunes.

```sql
create table public.songs (
  id bigint generated by default as identity primary key,
  spotify_track_id text unique not null,

  title text not null,
  artist text not null,

  cover_url text,
  preview_url text,

  created_at timestamp with time zone default timezone('utc'::text, now()) not null,
  updated_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- Activer Row Level Security
alter table public.songs enable row level security;

-- Tout le monde peut consulter les morceaux
create policy "Songs are viewable by everyone." on public.songs
  for select using (true);
```

## Table `playlist_songs`

Table de liaison entre les playlists et les morceaux.

```sql
create table public.playlist_songs (
   playlist_id bigint references public.playlists(id) on delete cascade,
   song_id bigint references public.songs(id) on delete cascade,

   position integer not null,

   primary key (playlist_id, song_id)
);
```

## Trigger pour la création automatique de profil

Optionnel mais recommandé pour créer un profil dès qu'un utilisateur s'inscrit (via Google).

```sql
-- Insérer automatiquement un profil à l'inscription
create function public.handle_new_user()
returns trigger as $$
begin
  insert into public.profiles (id, username, avatar_url, id_role)
  values (new.id, new.raw_user_meta_data->>'full_name', new.raw_user_meta_data->>'avatar_url', 1);
  return new;
end;
$$ language plpgsql security definer;

create trigger on_auth_user_created
  after insert on auth.users
  for each row execute procedure public.handle_new_user();
```

## Migration — ajout des rôles (bases existantes)

Si la table `profiles` existe déjà sans `id_role`, exécutez :

```sql
create table if not exists public.roles (
  id bigint generated by default as identity primary key,
  role text unique not null
);

insert into public.roles (role) values ('User'), ('Admin')
on conflict (role) do nothing;

alter table public.profiles
  add column if not exists id_role bigint references public.roles(id) default 1 not null;
```

## Configuration Auth (Google OAuth)

Dans le dashboard Supabase :

1. **Auth > Providers** : activer Google OAuth
2. **Auth > URL Configuration** :
   - Site URL : `http://localhost:5173`
   - Redirect URLs : `http://localhost:3001/api/auth/callback`
3. Variables backend (voir `back/.env.example`) :
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `SUPABASE_JWT_SECRET`
   - `BACKEND_URL=http://localhost:3001`
   - `CLIENT_URL=http://localhost:5173`
